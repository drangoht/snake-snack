# Snake Snack

The classic game of Snake

Unity 6000.5.6f1 · C# · URP 2D · Input System · published on
[itch.io](https://Drangoht.itch.io/snake-snack).

**Where the game stands** (2026-08-30): the mechanics are complete — snake, apple, score, persistent
best, pause, death, refusal of the U-turn — the game opens on a **main menu** navigable with the
keyboard as well as the mouse, and **the feel is finished**: the snake glides, squashes when it
swallows, leans into its turns and looks where it is going; the apple pops in, the cell that kills you
lights up before the end screen. Two web versions have shipped (0.1.0, 0.2.0), the itch page stays
**in Draft**. Remaining before making it public: the graphical assets, the sound effects and the
music.

## Getting started

```powershell
# Build, launch, capture -- without ever opening the editor
& "tools/build.ps1" -Run
```

That is all: the first build **imports the project itself** (it generates `Library/` and
`ProjectSettings/` — reckon on ~20 min), so there is nothing to open in Unity Hub beforehand.

`build.ps1` finds Unity on its own among the Unity Hub installations, then keeps its path in
`tools/local.settings.json` (not versioned). If it does not find it — Unity installed on another
drive, for instance — teach it once:

```powershell
& "tools/configure.ps1" -UnityPath "<unity-folder>\6000.5.6f1\Editor\Unity.exe"
```

## Structure

```
Assets/
  Editor/            BuildTools · RenderPipelineSetup · SceneBuilder
  Scripts/Core/      BuildInfo and groundwork
  Scripts/Rules/     ⚠ PURE testable logic — no `using UnityEngine`
  Scripts/Gameplay/  MonoBehaviour
  Scripts/UI/        Screens, HUD
  Settings/          URP assets (pipeline, 2D renderer)
  Scenes/Game.unity  ⚠ ARTEFACT regenerated by SceneBuilder
  WebGLTemplates/    Host page of the web build
tests/               xUnit over Assets/Scripts/Rules/ — no engine required
tools/               build.ps1 · configure.ps1 · environment.ps1 · release_itch.ps1
                     serve_web.py · drive_game.py
docs/                GDD (+ gdd/) · PITFALLS_UNITY (+ pitfalls/) · RELEASE · DEVLOG · TEST_REPORT
.claude/             9 agents · 4 skills · 2 hooks
```

## The three structuring choices

**1. The scene is an artefact, not a source.** `Assets/Scenes/Game.unity` is regenerated by
`SceneBuilder.Build()` at every build. An object is added to the game **by writing code**, not by
clicking in the editor. In exchange, the whole game is driven from the command line — build, launch,
inject keys, capture — and therefore verified without a human hand.
⚠ Corollary: the scene comes out modified after every build. Discard it (`git checkout --`) unless
`SceneBuilder.cs` changed.

**2. Every numbered rule lives in `Assets/Scripts/Rules/`**, as a static class with no engine
dependency, with its tests. `dotnet test tests/SnakeSnack.Tests.csproj` runs in a few seconds, without
Unity — and a hook replays them after every edit.

**3. The binary carries its identity.** Every build writes `build_stamp.json` and a `v<version>-<sha>`
stamp shown at the bottom right. Neither a file's date (incremental build) nor the Windows metadata
(which describe the engine) say which version you are looking at. That stamp does.

## Useful commands

| Goal | Command |
|---|---|
| Windows build | `& "tools/build.ps1"` |
| Web build | `& "tools/build.ps1" -Target web` |
| Build + launch + capture | `& "tools/build.ps1" -Run -Capture docs/x.png` |
| Tests | `dotnet test tests/SnakeSnack.Tests.csproj` |
| Launch and capture | `py tools/drive_game.py --launch --capture docs/x.png` |
| Serve the web build | `py tools/serve_web.py` (⚠ **no cache** — see PITFALLS) |
| Publish | `& "tools/release_itch.ps1" -Version X.Y.Z -DryRun` |
| Regenerate the fonts | `py tools/generate_fonts.py` |
| Regenerate the menu illustration | `py tools/generate_snake_illustration.py --preview` |
| Say where Unity and Python are | `& "tools/configure.ps1" -UnityPath "..."` |

⚠ **The Unity editor must be closed** for any command-line build — `build.ps1` refuses to start
otherwise.
⚠ Only call `Unity.exe` by hand if you know why: its path changes from one machine to the next, and
launched with `&` in PowerShell it hands back control **immediately without doing anything**
(`Start-Process -Wait`). `build.ps1` handles both.
