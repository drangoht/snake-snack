## The agent team — delegate, but not at a loss

The nine agents in `.claude/agents/` are already listed with their description at the top of the
session — do not describe them again here. Who does what **and in which order**: **`GUIDE-EQUIPE.md`**.

⚠ **An agent starts from cold**: it re-reads CLAUDE.md, the GDD, the map, the pitfalls — around 8,000
tokens before its first action, which one may have just read oneself. Delegate when the task is **in
its speciality** *and* **big enough to amortise that** (designing a system, a test pass, a release). A
ten-line fix, a question, a read: do it yourself. When delegating, **pass in the instruction what you
already know** (files concerned, decision taken, pitfall identified) rather than making it rediscover
that.

⚠ **An agent describing a stale state of the project is worse than an absent agent**: it gives false
instructions with authority. When a phase ends, re-read the agents it concerns.

## Conventions

- **Build**: `& "tools/build.ps1"` → `Build\Windows\SnakeSnack.exe`; `-Target web` →
  `Build\Web\`; `-Run` chains launch and capture. ⚠ The Unity editor must be **closed**.
- **Publishing**: `tools/release_itch.ps1 -Version X.Y.Z` (try `-DryRun` first). The script sets
  `bundleVersion` itself — **do not edit it by hand**.
- **The scene is an ARTEFACT**: `Assets/Scenes/Game.unity` is regenerated by `SceneBuilder.Build()` at
  every build. An object is added to the game **by writing code**, not by clicking in the editor. It
  comes out modified after every build — discard it (`git checkout --`) unless `SceneBuilder.cs`
  changed.
- **Pure testable logic**: `Assets/Scripts/Rules/` — static classes **with no engine dependency**. The
  `MonoBehaviour`s delegate to them. Tests: `dotnet test tests/SnakeSnack.Tests.csproj` (no engine, no
  build required; replayed by a hook after every edit).
- **Nothing obsolete**: URP (never Built-in), Input System (never the old Input Manager). Report any
  deprecation warning without waiting to be asked.
- **No hard-coded tool path** (Unity, Python): `tools/environment.ps1` resolves them and remembers
  them in `tools/local.settings.json`, not versioned.
- Style: PascalCase for classes/methods, `_camelCase` for private fields, `readonly` by default.
  Comments in English, and they explain the **why**.
- Tuning is adjusted **without recompiling** as soon as a value deserves to be tried several times.
- UI palette: <!-- hex codes --> · Font: <!-- family -->
- ⚠ Three pitfalls that raise nothing and that one meets everywhere — the detail in the file named:
  **AZERTY** keyboard (`docs/pitfalls/inputs.md`), `Art/` ≠ `Resources/`
  (`docs/pitfalls/assets-import.md`), Unity's misleading exit code (`docs/pitfalls/build.md`).

## Documentation upkeep

- Updated **in the commit** that makes what they describe false: `docs/gdd/`, `/carte-projet`,
  `docs/pitfalls/`. A stale document gives a false answer with authority.
- `README.md` — updated at every phase change or major addition.
- ⚠ **Every document re-read at every task has a ceiling** (this file: 80 lines; `GDD.md`,
  `/carte-projet`: 150; a pitfalls or system file: 150). Once reached, **split** it and leave an index.
  Without that reflex, the cost per task climbs until it exceeds the task.
