## The architecture rule that overrides everything

> **Every numbered rule — curve, threshold, table, formula — goes into `Assets/Scripts/Rules/`, as a
> static class with NO engine dependency whatsoever, with its tests.** The `MonoBehaviour`s delegate.

That is what makes the game tunable: these tests run in a few milliseconds because they never touch the
engine, and the `run-rules-tests.ps1` hook replays them at every edit. A class in `Rules/` that would
need `using UnityEngine` signals a bad split — it is up to the caller to do the engine work.

The tests do not aim at line coverage but at **regressions of intent**: a test must lock down *what the
design forbids*, not paraphrase the implementation.

## The scene is an artefact, not a source

`Assets/Scenes/Game.unity` is **regenerated by `SceneBuilder.Build()`** at every build. To add an object
to the game, you write code in `SceneBuilder`, you do not click in the editor. In exchange, the whole
game is driven in batchmode — which is what lets you verify your own work.

⚠ Corollary: the scene comes out **modified after every build** (every `fileID` renumbered). Discard it
(`git checkout --`) unless `SceneBuilder.cs` changed.

## Non-negotiable conventions

- PascalCase for classes/methods · `_camelCase` for private fields · `readonly` by default.
- **Nothing obsolete**: URP (never Built-in), the Input System package (never the old Input Manager).
  If a deprecation warning appears in a log, report it without waiting to be asked — that is an
  explicit instruction from the project owner.
- ⚠ **The project owner's keyboard is AZERTY.** `KeyCode` as well as `Key` designate a **physical
  position on a QWERTY keyboard**, never the printed character: `Key.A` falls under the key marked
  **Q**. That is the intended behaviour, not a bug. Corollary: ban `A`, `Q`, `Z`, `W`, `M` for global
  shortcuts — prefer `Tab`, `R`, the digits or the arrows, whose position is common to both layouts.
- **Never a hard-coded colour** nor an ad hoc style: go through the project's palette.
- **Never hard-coded text** if the game is localised.
- Tuning is adjusted **without recompiling** (JSON in `StreamingAssets/` or a ScriptableObject) as soon
  as a value deserves to be tried several times.
- Comments in English, and they explain the **why**. A comment that paraphrases the code is noise; one
  that says "without this guard rail, a 2nd boss appeared every 28 s" prevents a regression.

## Before shipping

- `dotnet test tests/SnakeSnack.Tests.csproj` → everything green.
- Unity build with no error and no new **warning**.
- **Verify in game, not only in tests.** A gameplay change is observed on screen: the
  **`/verifier-en-jeu`** skill (`tools/drive_game.py` builds, launches, injects keys and captures).
  *If you have not done it, say so explicitly instead of letting it be believed that you have.*
- Update, **in the same commit**, whatever your change makes false: `/carte-projet`, the
  `docs/pitfalls/<domain>.md` concerned, `docs/gdd/<system>.md`.
